# Weaponbreaker

Мод Valheim про выбивание оружия при парировании и риск потерять оружие от сильного удара врага.

Основная концепция и текущие решения находятся в [DESIGN.md](DESIGN.md).

## Сборка

Нужны .NET SDK с поддержкой C# 10, установленный Valheim и профиль мод-менеджера с BepInExPack Valheim.

1. Скопируйте `Weaponbreaker.local.props.example` в `Weaponbreaker.local.props` рядом с `.csproj`.
2. Впишите `ValheimGamePath` — папку игры с `valheim_Data`, и `ValheimProfilePath` — папку профиля с `BepInEx/core`.
3. Перезагрузите проект в Rider и запустите сборку или выполните `dotnet build WeaponbreakerMod.sln`.

Локальный файл путей исключён из Git. Он подключается самим проектом, поэтому работает и в IDE, и в командной строке. Вместо файла можно задать переменные окружения `VALHEIM_GAME_PATH` и `VALHEIM_PROFILE_PATH` или свойства MSBuild `ValheimGamePath` и `ValheimProfilePath`. Для нестандартной структуры доступны свойства `ValheimManagedPath` и `BepInExPath`.

Сборка использует `BepInEx.dll`, `0Harmony.dll`, `UnityEngine.dll`, `UnityEngine.CoreModule.dll` и `assembly_valheim.dll` из указанных папок. При отсутствии DLL сборка сообщит, какой файл не найден.

## Реализация

Текущая реализация содержит BepInEx-каркас и боевые сценарии Weaponbreaker:

- Harmony-детектор получает только успешный `Humanoid.BlockAttack` в окне perfect block;
- сервис проверяет владельца ZDO врага, whitelist и шанс правила с учётом типа предмета, которым выполнено парирование;
- поддержанное оружие снимается с врага и создаётся как настоящий `ItemDrop`;
- для enemy-only оружия используется зарегистрированный fallback из `ObjectDB`;
- выпавший предмет получает сетевые маркеры Weaponbreaker и отключённый автосбор игроком.
- успешный блок или парирование щитом защищает оружие игрока от выпадения при этом ударе даже при остаточном уроне; блок оружием и сорванный блок щитом сохраняют шанс обезоруживания при потере здоровья.
- JSON-конфигурация содержит переключатели механик и значения шансов по врагам: вооружённые враги имеют два ползунка, безоружные — только шанс выбить оружие игрока;
- базовый шанс потери оружия у вооружённых врагов — 30%; навык оружия или щита изменяет итоговый шанс, нейтральная точка — 25;
- окно perfect parry остаётся ванильным; кулдауны настраиваются (враг — 8 секунд, подбор — 8 секунд, игрок — 15 секунд), настройки хоста применяются ко всем клиентам.

Расширение whitelist остаётся следующим вертикальным срезом.

Текущий код уже содержит эти пути: обратное выбивание проверяется после реального урона, скрытая атака из лука удваивает шанс выбивания врага, а AI врага возвращается к сохранённым координатам своего оружия. Предмет, выбитый из игрока, врагом не подбирается.

## Совместимость с EpicLoot

EpicLoot подключается автоматически, если BepInEx загрузил плагин `randyknapp.mods.epicloot`. Он остаётся необязательной зависимостью: без него Weaponbreaker выбрасывает обычное оружие, включая случай, когда в конфиге включено переопределение шанса зачарования. Несовместимый API отключает интеграцию с предупреждением в логе.

По умолчанию Weaponbreaker использует загруженные таблицы EpicLoot для конкретного моба: шанс и количество бросков добычи, уровень и звёзды, настройки категорий предметов, веса редкостей и удачу. Первый подходящий бросок зачарованной экипировки определяет редкость выбитого оружия. Броски материалов, камней и неопознанных предметов оставляют его обычным. Эффекты и сокеты для самого выбитого оружия генерирует EpicLoot; предмет остаётся аналогом оружия врага из таблицы Weaponbreaker. Обычный дроп EpicLoot при смерти врага работает отдельно.

В Configuration Manager у каждого обезоруживаемого семейства врагов (`Skeleton`, `Draugr`, `Fuling`, `Charred`, `Dvergr`) есть два новых параметра:

- `OverrideEpicLootEnchantChance` — чекбокс переопределения шанса, по умолчанию выключен;
- `EpicLootEnchantChance` — ползунок от `0` до `1`: `0.1` означает 10%, `1` — 100% среди успешно выбитых оружий. Работает только с включённым чекбоксом и загруженным EpicLoot.

Дефолты ползунка растут со сложностью врага: скелет — 15%, драугр — 20%, фулинг — 25%, двергр — 30%, обугленный — 35%. Чекбокс расположен непосредственно над ползунком. В старых JSON-файлах без этого поля используются дефолты соответствующего семейства врагов.

При переопределении выполняется один бросок заданного шанса, а редкость выбирается из подходящих записей экипировки в таблицах моба с учётом звёзд и удачи. Шанс дропа EpicLoot и его соотношение категорий больше не уменьшают этот шанс. Если подходящих записей нет или предмет нельзя зачаровать, выпадает обычное оружие. Эффекты по-прежнему создаёт EpicLoot. Эти настройки синхронизируются с хоста вместе с остальными настройками Weaponbreaker.

Результат первого выбивания сохраняется в ZDO врага, включая обычное оружие. Повторное выбивание после подбора врагом, смена владельца ZDO и загрузка сохранённого состояния используют тот же результат. Смена настроек действует на оружие, для которого результат ещё не определён.

## Сеть и ZDO (0.1.5)

Обработчики подключения и обновления `ZNet` больше не патчатся. Синхронизация работает в `Update` самого плагина с проверкой раз в секунду. Клиент запрашивает конфигурацию после появления своего персонажа; сервер отвечает адресно только после получения валидного ZDO этого персонажа с правильным владельцем. Клиентам без запроса мод ничего не рассылает. Настройки повторно отправляются только при изменениях на хосте.

Хост определяет переключатели механик, шансы, кулдауны и доступность интеграций EpicLoot/DualWield. Рабочий снимок отделён от локальных настроек Configuration Manager; локальные изменения клиента не меняют правила текущей сессии. До получения настроек клиентская боевая логика приостановлена. При выходе из мира очищаются настройки сессии и локальные ссылки на врагов/оружие.

Изменения инвентаря и ZDO выполняет штатный владелец объекта Valheim, без принудительной передачи владения серверу. Перед записью проверяются валидность ZDO, ненулевой ID и владение. Записи ограничены ключами `weaponbreaker.*`. Пока предмет отсутствует в сцене, но его ZDO существует, ссылка врага на оружие сохраняется. Мод не записывает координаты персонажа, его файл сохранения или состояние зон мира.

В `BepInEx/LogOutput.log` сообщения `[Network]` показывают начало сессии, готовность персонажа/пира, запрос и применение конфигурации. `[ZDO]` содержит ID персонажа, владельца и предмета при успешном обезоруживании. Повторяющиеся исключения ограничены одним сообщением за 10 секунд.

В 0.1.6 подтверждённое парирование пересылается владельцу ZDO врага, если защитник и враг обрабатываются на разных пирах. Получатель проверяет владельца ZDO защитника, дистанцию, возраст и уникальность события, зарегистрированный prefab блокирующего предмета и допустимый коэффициент навыка. Шанс берётся из конфигурации хоста; коэффициент навыка сообщает владелец защитника, поскольку удалённый экземпляр игрока не содержит полного локального состояния навыков. Это проверка корректности событий, а не защита от модифицированного клиента. `[Parry]` показывает маршрут события, базовый/итоговый шанс, результат броска и причины отказа. Для этой тестовой сборки используйте 0.1.6 у всех участников.

Локальные проверки: `dotnet run --project verification/NetworkSync/NetworkSync.csproj -c Release` проверяет протокол и жизненный цикл на управляемых заменах API; `verification/Verify-ShieldBlocks.ps1` проверяет блокирование на типах и IL установленного Valheim; `verification/Verify-UpdatePackages.ps1 -ModNames Weaponbreaker -PackageVersion 0.1.5` проверяет финальный ZIP и JSON в настоящем Mono Valheim. Для подтверждения загрузки мира нужен отдельный запуск игры с подключением клиента.

## Структура исходников

- `Breaker/Services/Disarming` — условия и сценарии обезоруживания;
- `Breaker/Services/Weapons` — выбор оружия, сетевой дроп и возврат оружия врагу;
- `Breaker/Services/Loot` — сохранение результата дропа;
- `Breaker/Compatibility/EpicLoot` — обнаружение EpicLoot, работа с его таблицами и API.

Папки `packaging` и `verification` используются локально и исключены из Git.
