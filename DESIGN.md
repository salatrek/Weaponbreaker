# Weaponbreaker — концепция и техническая спецификация

## Статус документа

Это исходная спецификация мода Weaponbreaker, собранная по результатам обсуждения концепции. Документ предназначен как контекст для дальнейшей разработки в новом чате Codex.

Проект отдельный и не связан с модом `MyEmotions`.

## Основная идея

Успешное парирование может выбить оружие из рук врага. Оружие становится настоящим предметом Valheim, выпадает на землю и подбирается игроком вручную.

Механика должна создавать короткое тактическое окно, а не превращать каждый бой в автоматический сбор добычи:

1. Игрок парирует подходящую атаку.
2. С заданным шансом оружие врага выбивается.
3. Враг временно остаётся без оружия.
4. Оружие появляется на земле как реальный `ItemDrop`.
5. Автосбор игрока его игнорирует.
6. Игрок должен навести взгляд на предмет и подобрать его обычным взаимодействием.

Обратная механика работает отдельно: некоторые враги могут выбить оружие у игрока, если их атака нанесла настоящий урон. Успешный блок или парирование щитом защищает оружие в другой руке; защита оружием такой гарантии не даёт.

## Правила парирования и выбивания

### Что считается парированием

В первой версии используется именно ванильный perfect block, а не любой успешный блок:

1. При начале блока Valheim запускает собственный таймер блока.
2. Если удар приходит раньше ванильного порога `0.25` секунды и предмет имеет `m_timedBlockBonus > 1`, игра считает это perfect block.
3. Только после такого результата Weaponbreaker бросает шанс выбивания.
4. Если удар пришёл после `0.25` секунды, это обычный блок: он может поглотить урон, но шанс выбивания равен нулю.
5. Если блок не сработал, игрок получил настоящий урон — шанс выбивания оружия врага также не бросается.

Таким образом, «неидеальное парирование» не превращается в ослабленный шанс. В текущем дизайне это обычный блок без выбивания; это сохраняет требование точного тайминга и не позволяет безопасно держать блок ради постепенного обезоруживания.

### Формула шанса

Для каждого вооружённого врага задаётся базовый `EnemyWeaponDisarmChance` (по умолчанию 30%). Он означает шанс после perfect block одноручным оружием игрока при навыке 25. Для остальных типов блока применяются внутренние множители:

| Предмет игрока | Множитель | Шанс при базе 30% и навыке 25 |
|---|---:|---:|
| Щит | 0.25 | 7.5% |
| Одноручное оружие | 1.0 | 30% |
| Двуручное оружие | 1.25 | 37.5% |

Множители и ванильное окно `0.25` секунды являются внутренними правилами. Кулдауны настраиваются: повторное обезоруживание врага и возврат к оружию — по 8 секунд, обезоруживание игрока — 15 секунд. Сохранённые настройки BepInEx применяются при запуске и имеют приоритет над значениями JSON; хост передаёт действующие параметры клиентам.

Базовые шансы выбить оружие врага:

| Способ парирования | Базовый шанс |
|---|---:|
| Щит | 7.5% |
| Одноручное оружие без щита | 30% |
| Двуручное оружие | 37.5% |

Точные значения могут быть переопределены правилом конкретного врага или типа оружия.

Парирование стрелы или другого снаряда не обезоруживает лучника. Лучник не получает `Disarmed` только потому, что его стрела была парирована.

Если существо атакует без оружия — например, руками или встроенной атакой монстра — оно не может потерять оружие, которого нет.

## Whitelist врагов

Мод не должен пытаться автоматически анализировать всех существ Valheim. Используется заранее подготовленный список поддерживаемых врагов. Для каждого врага заранее задаются:

- prefab врага;
- список поддержанных вариантов оружия и предметов-дропов;
- шанс выбить оружие врага после perfect parry;
- шанс выбить оружие у игрока;
- разрешён ли дроп оружия врага.

Предлагаемая модель правила:

```text
EnemyPrefab
WeaponVariant
DropPrefab
EnemyWeaponDropChance
PlayerDisarmChance
CanDropWeapon
CanDisarmPlayer
```

Пример конфигурационной записи для вооружённого врага:

```json
{
  "Draugr": {
    "Enabled": true,
    "EnemyWeaponDisarmChance": 0.30,
    "PlayerDisarmChance": 0.02
  }
}
```

Для безоружных существ, например кабана, комара или пиявки, в конфигурации остаётся только `PlayerDisarmChance`: им нечего выбивать из собственных рук.

Для каждого врага используется одна секция `Enemies.<EnemyId>`, а не отдельная секция для каждого варианта оружия. Внутренняя таблица правил всё ещё различает конкретный меч, топор или булаву и выбирает соответствующий предмет-дроп.

Список должен быть захардкожен в коде как источник истины, а конфигурация может использоваться только для баланса и включения/отключения правил.

## Предварительные правила врагов

Это стартовый набор, который нужно подтвердить по актуальным prefab-именам установленной версии Valheim перед реализацией:

| Враг/вариант | Оружие врага | Возможный дроп | Шанс выбить оружие игрока |
|---|---|---|---:|
| Skeleton, меч | Sword | Bronze Sword | 0.5% |
| Skeleton, булава | Mace | Iron Mace | 1% |
| Draugr, топор | Axe | Iron Axe | 1.5% |
| Draugr Elite, меч | Sword | Iron Sword | 4% |
| Fuling, дубина | Club | Club | 3% |
| Fuling, меч | Sword | Blackmetal Sword | 4% |
| Fuling, копьё | Spear throw | Wolf Fang Spear | 5% |
| Fuling Berserker | Enemy great weapon | заранее выбранный двуручный аналог | 10% |
| Goblin Shaman | Staff/ability | заранее выбранный staff или без дропа | 8% |
| Charred Warrior | Enemy greatsword | Flametal two-handed weapon | 12% |
| Dvergr Rogue | Enemy weapon | заранее выбранный аналог | 8–12% |
| Boar | Нет | Нет | 0.5% |
| Neck | Нет | Нет | 0.5% |
| Greydwarf и другие безоружные | Нет | Нет | низкий шанс по отдельному правилу |

Луки не должны автоматически создавать отдельную ближнюю атаку. Парирование стрелы не даёт выбивание. Лучники могут присутствовать в whitelist для явного описания их атак, но для обычной bow-атаки `CanDropWeapon` должен быть выключен.

## Enemy-only оружие и fallback

Не каждое оружие, которое визуально держит враг, является предметом игрока. Если prefab отсутствует в `ObjectDB` или не является пригодным `ItemDrop`, нельзя пытаться создать из него подбираемый предмет напрямую.

Для таких случаев используется заранее заданная таблица сопоставления:

```text
enemy-only weapon → registered player weapon
```

Примеры:

```text
draugr_axe     → AxeIron
draugr_sword   → SwordIron
skeleton_sword → SwordBronze
goblin_club    → Club
goblin_spear   → SpearWolfFang
charred_sword  → THSwordSlayer или другой заранее выбранный аналог
```

Если в таблице нет безопасной замены, оружие не выбрасывается. Это предпочтительнее, чем создавать невзаимодействующий или дублирующий предмет.

## Обратное выбивание оружия у игрока

Некоторые враги могут выбить активное оружие игрока, если одновременно выполнены условия:

- атака попала в игрока;
- здоровье игрока действительно уменьшилось;
- удар не был успешно заблокирован или парирован щитом;
- у игрока есть активное оружие;
- персональный кулдаун игрока истёк.

Персональный кулдаун после выбивания оружия у игрока: **15 секунд**.

Обратная проверка выполняется после фактического уменьшения здоровья игрока в `Character.RPC_Damage` на владельце персонажа. При успешном блоке или perfect parry щитом оружие игрока не выпадает даже при остаточном уроне. Блок или парирование оружием с потерей здоровья сохраняет обычный шанс обезоруживания. Сорванный блок щитом из-за выносливости или ошеломления не даёт защиты от обезоруживания. Промах и полностью поглощённый удар не запускают проверку. Успех блока определяется по выполнению ванильной ветки `HitData.BlockDamage` для конкретного удара и персонажа, а не только по таймеру или наличию щита. Выпавший предмет помечается как выбитый игроком и исключается из автосбора, но не получает `sourceEnemy`, поэтому враг не может подобрать оружие игрока.

Отдельно поддерживается усиленный сценарий атаки игрока: если враг действительно получил урон от стрелы из лука во время скрытности и урон содержит ванильный backstab-бонус, шанс выбить оружие врага увеличивается в **2 раза**. Этот путь не заменяет perfect parry, а является дополнительным явно заданным исключением.

Рекомендуемые дополнительные ограничения:

- за одну атаку выбрасывается только один предмет;
- щит не выбивается этой механикой, если отдельно не добавлено такое правило;
- несколько врагов не могут обойти кулдаун повторными попаданиями;
- если игрок безоружен, эффект не срабатывает;
- шанс считается отдельно от шанса дропа оружия врага.

Диапазон `PlayerDisarmChance` — от 0.5% до 25%. Значение 25% следует оставлять только редким сильным противникам или особым правилам, иначе частые попадания быстро начнут раздражать игрока.

### Зависимость от навыка

К базовому шансу применяется множитель навыка используемого предмета. Нейтральная точка — уровень 25:

- уровень 25 даёт множитель `1.0`;
- ниже 25 шанс обезоружить врага плавно уменьшается от `0.75` до `1.0`, а шанс потерять своё оружие плавно увеличивается от `1.25` до `1.0`;
- выше 25 шанс обезоружить врага растёт от `1.0` до `1.25`, а шанс потерять своё оружие уменьшается от `1.0` до `0.75`;
- для щита используется навык `Blocking`, для оружия — его ванильный `SkillType`.

Итоговый шанс ограничивается диапазоном от 0 до 100%. Множители навыка не выносятся в конфиг.

При навыке `s` от 0 до 100 множитель обезоруживания врага равен `0.75 + s / 100` до уровня 25 включительно и `1 + (s - 25) / 300` выше 25. Множитель риска потерять своё оружие равен `1.25 - s / 100` до 25 и `1 - (s - 25) / 300` выше 25.

Итог для врага: `clamp01(база × множитель способа × множитель навыка)`. Для игрока: `clamp01(PlayerDisarmChance × множитель риска)`. Повышение базы врагов с 20% до 30% не меняет `PlayerDisarmChance`.

Пересчёт для базы 30% (каждый столбец использует навык соответствующего оружия; щит — «Блокирование»):

| Навык | Щит ×0.25 | Одноручное ×1 | Двуручное ×1.25 | Скрытая стрела ×2 |
|---:|---:|---:|---:|---:|
| 0 | 5.625% | 22.5% | 28.125% | 45% |
| 25 | 7.5% | 30% | 37.5% | 60% |
| 50 | 8.125% | 32.5% | 40.625% | 65% |
| 100 | 9.375% | 37.5% | 46.875% | 75% |

Обычный блок даёт 0%; во время кулдауна новая попытка обезоруживания не проходит. Шансы в таблице относятся к одной допустимой попытке, а не гарантии за несколько атак.

## Поведение выпавшего оружия

Оружие врага должно создаваться как настоящий сетевой `ItemDrop`, а не как визуальная копия.

При создании нужно сохранить по возможности:

- prefab предмета;
- качество;
- прочность;
- вариант модели;
- прочие данные `ItemData`, если они совместимы с предметом игрока.

У выпавшего предмета должен быть сетевой маркер, например:

```text
weaponbreaker.disarmed = true
weaponbreaker.sourceEnemy = enemyZdoId
weaponbreaker.pickupLockedUntil = serverTime + 6
```

`m_autoPickup = false` нужно использовать как локальную часть поведения, но не считать его достаточным сетевым флагом.

Игрок может подобрать оружие вручную сразу после появления, если хочет. Шестисекундная задержка относится к возможности врага подобрать своё оружие обратно.

## Повторный подбор врагом

После выбивания враг не должен подобрать оружие примерно 6 секунд.

После истечения задержки враг может попытаться вернуть оружие, если:

- предмет всё ещё существует;
- предмет находится в допустимом радиусе;
- враг жив и способен экипироваться;
- игрок ещё не забрал предмет.

При выбивании в ZDO врага сохраняются ZDOID выпавшего предмета и точная координата его появления. После истечения шести секунд AI не ищет произвольное оружие рядом: он возвращается именно к сохранённой точке и пытается подобрать именно этот сетевой `ItemDrop`. Если предмет уже поднят игроком или уничтожен, второй предмет не создаётся.

Подбор врагом должен быть отдельным явным AI-путём и не зависеть от автосбора игрока.

## Сетевое взаимодействие

Мод рассчитан на хостируемый Valheim-сервер, где у хоста и игроков установлен одинаковый мод.

Правила авторитетности:

1. Только владелец ZDO врага фиксирует успешное выбивание.
2. Только владелец врага снимает оружие и меняет его состояние.
3. Только один владелец создаёт сетевой `ItemDrop`.
4. Lock и связь с врагом записываются в ZDO.
5. Ручной подбор использует стандартный ownership flow `ItemDrop`.
6. У всех клиентов `Player.AutoPickup` должен распознавать маркер Weaponbreaker и пропускать такие предметы.

Для загруженных на клиентах предметов маркер повторно применяется в `ItemDrop.Load`, а `m_autoPickup` устанавливается в `false`. Ручное взаимодействие через `ItemDrop.Interact` при этом не блокируется.

Все игроки должны иметь:

- одинаковую версию Weaponbreaker;
- одинаковую версию игры;
- одинаковую таблицу сопоставления;
- одинаковые обязательные зависимости;
- совместимый набор модов.

Если у клиента нет Weaponbreaker, он может увидеть оружие как обычный предмет и автоматически подобрать его. Поэтому для полноценного поведения мод должен быть установлен у всех участников.

Для первой версии лучше использовать только зарегистрированные ванильные предметы игрока в качестве результата fallback. Это уменьшит риск рассинхронизации prefab-ов и зависимости от модовых оружий.

## Открытые технические вопросы

Перед началом реализации нужно проверить в актуальной `assembly_valheim.dll` и prefab-данных:

- точку, где надёжно определяется успешное парирование;
- точку, где фиксируется факт реально прошедшего урона;
- какие поля Humanoid содержат оружие врага;
- как конкретные враги хранят варианты оружия;
- сетевой способ создания `ItemDrop` в текущей версии игры;
- какие prefab-ы оружия зарегистрированы в `ObjectDB`;
- какие enemy-only prefab-ы требуют fallback;
- как реализовать подбор оружия врагом без дублирования предмета.

## Название

Рабочее название проекта: **Weaponbreaker**.

Оно подходит и для механики выбивания оружия у врагов, и для обратной механики, где враги могут выбить оружие у игрока.
